# 헬스 기록

헬스장 운동을 세트 단위로 기록하는 개인용 웹앱입니다. 휴대폰 브라우저에서 쓰도록 만들었고, 홈 화면에 추가하면 앱처럼 열립니다.

로그인이 없습니다. 기록은 폰의 브라우저 저장소(IndexedDB)에 저장되고, 한 번 연 뒤에는 인터넷 없이도 동작합니다. 클라우드 백업을 켜면 암호화한 사본을 내 Cloudflare에 자동으로 올려 둡니다(기본은 꺼짐).

## 지금 되는 것

- **운동 기록**: 운동을 시작하고 종목별로 세트의 무게(kg)와 횟수를 적은 뒤 완료를 체크합니다. 종목 순서는 화살표로 바꿉니다. 세트 번호를 누르면 그 세트의 설정 창이 열려 웜업 표시(볼륨 계산에서 빠짐), 힘든 정도(RPE 6~10), 세트 삭제를 할 수 있습니다.
- **지난 세트 자동 채우기**: 종목을 추가하면 그 종목을 마지막으로 했을 때의 무게와 횟수가 미리 채워집니다.
- **휴식 타이머**: 세트를 완료하면 자동으로 시작합니다. 기본값은 60~300초 중에서 고르거나 직접 적고, 종목마다 따로 정할 수도 있습니다. 쉬는 중에 15초씩 늘리거나 줄일 수 있고, 끝나면 진동과 소리로 알립니다.
- **기록 보기**: 지난 운동을 달별로 보고, 세트를 고치거나 기록을 지우고, 같은 종목으로 다시 시작할 수 있습니다.
- **종목**: 기본 종목 89개(유산소 7개 포함)가 들어 있고, 내 종목을 추가하거나 이름, 부위, 기구를 고칠 수 있습니다. 쓰지 않는 종목은 숨길 수 있고(기록은 그대로 남고, 종목 선택 아래의 "숨긴 종목"에서 되돌립니다), 기록이 없는 내 종목은 지울 수 있습니다. 종목마다 시트 높이 같은 메모를 적어 두면 운동 중 카드에 보입니다. 종목 이름은 띄어쓰기 없이 찾아도 나옵니다.
- **맨몸 종목의 추가 무게와 시간 종목**: 풀업이나 딥스 같은 맨몸 종목은 무게 칸에 추가 무게를 적을 수 있습니다(비우면 맨몸). 플랭크처럼 버티는 종목은 횟수 대신 시간(초)으로 기록합니다. 내 종목을 만들 때 횟수, 시간, 유산소 중에서 고릅니다.
- **유산소**: 러닝머신, 실내 자전거, 스텝밀, 일립티컬, 로잉 머신, 달리기, 줄넘기가 들어 있습니다. 무게와 횟수 대신 시간(분)과 거리(km)를 적고, 스텝밀은 거리 대신 오른 층수를 적습니다. 세트 번호를 누르면 기구의 강도(레벨)도 적을 수 있습니다. 유산소는 볼륨과 부위별 세트 수에 들어가지 않고, 세트를 완료해도 휴식 타이머가 돌지 않습니다. 통계에는 이번 주에 한 유산소 시간과 최근 12주의 주별 시간이 따로 나옵니다.
- **스톱워치**: 시간으로 적는 종목(플랭크 같은 시간 종목과 유산소)은 카드의 "시간 재기"로 재서 멈추면 그 시간이 세트에 적히고 완료로 표시됩니다. 시간 종목에 목표 시간이 있으면 지났을 때 한 번 알립니다. 재는 중에 앱을 닫았다 열어도 이어서 잽니다.
- **웜업 세트 만들기**: 무게를 드는 종목 카드의 "웜업"을 누르면 본 세트 무게를 보고 약 40% × 8회, 60% × 5회, 80% × 3회의 웜업 세트를 본 세트 앞에 넣습니다. 바벨 종목은 맨 앞에 바만 드는 세트(10회)를 더하고, 가진 원판으로 맞출 수 있는 무게로 고릅니다.
- **원판 계산**: 바벨 종목 카드의 "원판"을 누르면 세트마다 한쪽에 끼울 원판을 "20 + 10 + 2.5"처럼 보여 줍니다. 바 무게(기본 20kg)와 가진 원판은 설정의 "바와 원판"에서 정합니다.
- **슈퍼세트**: 운동 중이나 루틴 편집에서 종목 사이의 "슈퍼세트로 묶기"를 누르면 두 종목(이어서 누르면 셋 이상)이 한 묶음이 됩니다. 묶음 안에서는 마지막 종목의 세트를 마쳤을 때만 휴식 타이머가 돕니다. 묶음은 함께 옮겨지고, 루틴과 "같은 운동 다시 하기"에도 따라갑니다.
- **주간 목표와 연속 기록**: 설정이나 홈에서 주에 몇 번 운동할지 정하면 홈에 이번 주 진행(월요일 시작)과 목표를 채운 주가 몇 주 이어졌는지 나옵니다. 끝낸 운동만 셉니다.
- **루틴**: 자주 하는 종목 묶음을 종목별 세트 수, 목표 횟수와 함께 저장하고 한 번에 시작합니다. 끝난 운동을 루틴으로 저장할 수도 있습니다. 최근에 쓰거나 고친 루틴이 홈에 보입니다.
- **다음 무게 추천**: 종목마다 지난 기록을 보고 "추천 62.5kg × 8"처럼 보여 줍니다. 눌러야 세트에 채워지고, 저절로 바뀌지는 않습니다. 설정에서 끌 수 있습니다. 규칙은 아래에 있습니다.
- **개인 기록(PR)**: 최고 중량, 추정 1RM, 최고 볼륨, 맨몸 종목의 최다 횟수와 최고 추가 무게, 시간 종목의 최장 시간을 세트에서 바로 계산합니다. 운동 중에 기록을 넘으면 그 세트에 표시되고, 운동 완료와 기록 상세에도 "새 기록 N개"로 나옵니다.
- **통계**: 이번 달 운동 횟수, 이번 주 볼륨, 12주 주별 운동 횟수와 볼륨, 최근 4주 부위별 세트 수, 운동 달력, 종목별 기록 목록을 보여 줍니다.
- **종목 상세**: 개인 기록, 추정 1RM과 최고 중량과 볼륨의 성장 그래프, 지난 기록, 그리고 추천에 쓰는 목표 횟수와 증량 단위 설정이 있습니다.
- **체중**: 통계 화면에서 오늘 체중을 적고, 그래프와 최근 4주 변화를 봅니다. 지난 날짜의 기록도 더하거나 고칠 수 있습니다.
- **백업과 복원**: 모든 기록과 루틴을 JSON 파일 하나로 내보내고 다시 불러옵니다. 폰을 바꿀 때도 이 파일로 옮깁니다. 백업한 지 14일이 넘으면 홈 화면에서 알려 주고, 그 자리에서 바로 백업할 수 있습니다.
- **클라우드 백업 (선택)**: 설정에서 켜면 기록 전체를 암호화해 이 앱을 올려 둔 내 Cloudflare에 자동으로 올려 두고, 새 폰에서 복구 코드로 되찾습니다. 아래 "클라우드 백업" 항목을 봐 주세요.
- **AI 추천 (선택)**: 설정에서 켜고 내 Anthropic API 키를 넣으면, 운동 중에 Claude가 최근 기록을 보고 종목마다 무게와 횟수를 이유와 함께 제안하고, 통계 화면에서 최근 8주 기록을 분석해 줍니다. 끝난 운동의 피드백을 받거나, 원하는 루틴을 글로 적어 루틴 제안을 받을 수도 있습니다. 누를 때만 요청하고, 꺼 두면 기록이 폰 밖으로 나가지 않습니다. 아래 "AI 추천" 항목을 봐 주세요.
- **CSV 내보내기**: 끝난 운동의 세트를 한 줄씩(무게, 횟수, 시간, RPE, 유산소의 거리와 층수와 강도 포함) 담은 표 파일로 받아 엑셀이나 구글 시트에서 볼 수 있습니다(복원용은 아님).
- **화면**: 폰의 밝은/어두운 화면 설정을 그대로 따릅니다.

## 쓰기 전에 알아 둘 점

- **클라우드 백업을 켜지 않으면 기록은 폰에만 있습니다.** 브라우저의 사이트 데이터를 지우거나 폰을 바꾸면 기록이 사라집니다. 설정에서 클라우드 백업을 켜 두거나, 가끔 백업 파일을 받아 폰 밖(클라우드 드라이브, 메일 등)에도 보관해 주세요.
- **홈 화면에 추가해서 쓰세요.** 앱처럼 전체 화면으로 열리고, 브라우저가 오래 쓰지 않은 사이트의 데이터를 정리해 버릴 가능성도 줄어듭니다.
  - 아이폰: Safari에서 주소를 연 뒤 공유 버튼의 "홈 화면에 추가"
  - 안드로이드: Chrome 메뉴의 "홈 화면에 추가" 또는 "앱 설치"
- **아이폰은 Safari와 홈 화면 앱의 저장 공간이 따로입니다.** Safari에서 쓰던 기록은 홈 화면 앱에 보이지 않습니다. 처음부터 홈 화면 앱에서 기록을 시작하거나, 백업 파일로 옮겨 주세요.
- **주소가 바뀌면 기록이 따라오지 않습니다.** 브라우저 저장소는 주소(도메인)마다 따로이므로, 배포 주소를 바꾸기 전에 백업하고 새 주소에서 복원해야 합니다. 항상 같은 주소로 열어 주세요.
- **휴식 타이머와 스톱워치의 알림은 앱이 화면에 떠 있을 때만 울립니다.** 쉬는 동안에는 화면이 꺼지지 않게 해 두지만(지원하는 브라우저에서), 다른 앱으로 넘어가 있으면 알림이 오지 않습니다. 돌아오면 남은 시간은 맞게 표시됩니다. 아이폰은 웹에서 진동을 지원하지 않고, 무음 모드에서는 소리가 나지 않을 수 있습니다.

## 다음 무게 추천 규칙

규칙 기반이며 인터넷이나 AI를 쓰지 않습니다. 종목의 마지막 기록에서 가장 무거운 무게로 한 본 세트(웜업 제외)를 봅니다.

- **목표 횟수**는 지난번 운동의 루틴 목표 횟수, 오늘 루틴의 목표 횟수, 종목 상세에서 정한 목표 횟수, 지난번 그 무게의 첫 세트 횟수 순서로 정합니다.
- 그 무게의 모든 세트에서 목표 횟수를 채웠으면 **증량 단위만큼 올립니다.** 기본값은 하체 5kg, 그 밖의 부위 2.5kg이고 종목 상세에서 바꿀 수 있습니다.
- 한 세트라도 못 채웠으면 **같은 무게로 다시** 합니다.
- 같은 무게에서 3번 연속 못 채웠으면 **약 10% 낮춥니다**(증량 단위의 배수로 내림). 기획에 없던 규칙으로, 정체에서 빠져나오도록 더했습니다.
- 맨몸 종목은 지난번 최고 횟수보다 1회 더를 추천합니다. 지난번에 추가 무게를 썼다면 무게 종목과 같은 규칙으로 추가 무게를 추천합니다.
- 시간으로 재는 종목은 지난번 가장 오래 버틴 시간보다 5초 더를 추천합니다. 목표 시간을 정했는데 못 채운 세트가 있으면 목표 시간을 다시 추천합니다.
- 유산소 종목에는 추천이 없습니다.
- 추천을 적용하면 아직 완료하지 않은 본 세트 중 지난번 최고 무게로 채워진 세트와 빈 세트만 바뀝니다. 피라미드처럼 가벼운 세트를 섞어 하면 그 세트들은 그대로입니다.

## AI 추천 (Claude)

기본으로 꺼져 있습니다. 켜지 않으면 위의 규칙 추천만 쓰고 인터넷도 쓰지 않습니다.

### 켜는 법

1. [Anthropic 콘솔](https://console.anthropic.com/settings/keys)에서 API 키를 만듭니다. 결제 수단을 등록하거나 크레딧을 충전해야 요청이 됩니다. Claude 앱 구독과는 별개로, 쓴 만큼 청구됩니다.
2. 앱의 설정에서 "AI 추천 (Claude)"를 켜고 키를 붙여 넣은 뒤 저장합니다.
3. "연결 확인"을 눌러 키와 모델이 맞는지 봅니다. 이 확인은 요금이 들지 않습니다.

### 하는 일

- **운동 중**: 종목을 추가한 뒤 "AI 추천 받기"를 누르면 Claude가 종목마다 무게, 횟수, 이유를 답합니다. 그 종목에서는 규칙 추천 대신 AI 추천이 보이고, "적용"을 눌러야 세트에 채워집니다. 적용 방식은 규칙 추천과 같아서 피라미드의 가벼운 세트는 그대로 둡니다.
- **통계**: "기록 분석 받기"를 누르면 최근 8주의 운동 빈도, 부위별 균형, 종목별 성장과 정체를 읽고 잘하고 있는 점, 살펴볼 점, 다음 4주 동안 해 볼 것을 짧게 정리합니다.
- **운동 뒤 피드백**: 기록 상세에서 "AI 피드백 받기"를 누르면 그 운동을 같은 종목의 지난 기록과 비교해 한 줄 총평과 짧은 항목 몇 개를 줍니다.
- **AI로 루틴 만들기**: 루틴 화면에서 "주 3회 상체/하체 분할"처럼 적으면 루틴을 1~4개 제안합니다. 미리 보고 고른 것만 보통 루틴으로 저장됩니다.
- **내 정보**: 설정의 AI 칸에 목표, 운동 경력, 주당 횟수, 참고할 점(부상, 피하고 싶은 동작)을 적어 두면 모든 요청에 함께 보내 답에 반영합니다.
- 받은 답은 폰에 저장되어 화면을 다시 열어도 다시 요청하지 않습니다. 새로 받으려면 "다시 받기"를 누릅니다. 운동 기록을 지우면 그 운동의 AI 답도 같이 지워집니다.

### 보내는 것과 보관

- 요청할 때 종목 이름과 부위, 날짜, 무게와 횟수, 힘든 정도(RPE), 목표 횟수와 증량 단위, 루틴 이름, 운동 메모와 종목 메모, 체중 기록, 적어 둔 내 정보가 Anthropic으로 전송됩니다. 운동 추천은 종목마다 최근 6번의 기록을, 기록 분석은 최근 8주를 보냅니다.
- API 키는 이 폰의 브라우저 저장소에만 저장됩니다. GitHub 저장소나 서버, 코드에는 들어가지 않고, 화면에는 앞뒤 몇 글자만 보입니다.
- 백업 파일에는 API 키와 이번 달 사용량이 들어가지 않습니다. 새 폰에서는 키를 다시 넣어야 하고, 백업을 복원해도 이 폰에 넣어 둔 키는 그대로 남습니다.
- 앱이 Anthropic API를 브라우저에서 바로 부릅니다. 개인용 앱이라 이렇게 했고, 다른 사람과 같이 쓰는 앱이라면 서버를 거쳐야 합니다.

### 모델과 비용

설정에서 모델을 고릅니다. 금액은 화면에도 나오는 어림값이고, 실제 청구는 콘솔에서 확인해 주세요.

운동 뒤 피드백은 운동 추천보다 조금 적게, 루틴 만들기는 조금 더 듭니다. 요청하기 전에 버튼 위에 어림값이 나옵니다.

| 모델 | 100만 토큰당 요금 (입력/출력) | 운동 추천 한 번 |
| --- | --- | --- |
| Opus 5.5 (기본) | $4 / $20 | 약 $0.06 |
| Sonnet 5.5 | $2 / $10 | 약 $0.03 |
| Haiku 5.5 | $0.10 / $0.50 | $0.01 미만 |

Opus와 Sonnet은 서버 측 대체 모델(`server-side-fallback` 베타)을 켜 두었습니다. 드물게 요청이 안전 검사에 걸려 거절되면 Anthropic이 같은 요청을 다른 모델로 다시 처리합니다. 그때는 실제로 답한 모델 이름이 화면에 나오고 비용도 그 모델 기준으로 셉니다. 설정의 "이번 달 N회 · 약 $X"는 이 폰에서 센 값이며 달이 바뀌면 0부터 다시 셉니다.

## 클라우드 백업

기본으로 꺼져 있습니다. 켜면 기록 전체(백업 파일과 같은 내용)를 암호화해서 이 앱을 올려 둔 내 Cloudflare Worker에 자동으로 올려 둡니다. 폰을 잃어버리거나 브라우저가 사이트 데이터를 지워도 새 폰에서 되찾을 수 있습니다. Cloudflare Workers에 배포한 주소에서만 쓸 수 있고, 개발 서버나 다른 호스팅에서는 설정 화면에 쓸 수 없다고 나옵니다.

### 켜는 법

1. 설정의 "클라우드 백업"에서 "클라우드 백업 시작"을 누릅니다. 복구 코드가 만들어지고 지금 기록이 올라갑니다.
2. 화면에 나온 복구 코드를 폰 밖(종이, 비밀번호 관리 앱 등)에 적어 둡니다. 나중에도 설정에서 다시 보거나 복사할 수 있습니다.

그 뒤로는 앱을 열 때, 다른 앱에서 돌아올 때, 운동을 끝냈을 때 바뀐 기록이 있으면 조용히 올립니다. 운동 중에는 올리지 않고, 바뀐 것이 없으면 올리지 않으며, 운동을 끝냈을 때를 빼면 5분에 한 번보다 자주 올리지 않습니다. 실패하면 설정 화면에 이유가 나오고 다음에 다시 시도합니다. 올리기에 성공하면 홈 화면의 백업 알림도 백업한 것으로 칩니다.

### 복구 코드

글자와 숫자 25자(다섯 자씩 다섯 묶음)이고 폰에서 무작위로 만듭니다. 헷갈리는 글자(I, L, O, U)는 쓰지 않습니다. 이 코드에서 두 가지가 나옵니다. 하나는 서버에 보내는 토큰이고, 하나는 백업을 암호화하는 키입니다. 키는 폰 밖으로 나가지 않으므로 서버에는 암호문만 있습니다.

- 복구 코드는 클라우드의 백업을 되찾는 하나뿐인 열쇠입니다. 잃어버리면 클라우드의 백업은 누구도 열 수 없습니다.
- 코드를 아는 사람은 백업을 내려받아 볼 수 있습니다. 남에게 보여 주지 마세요.
- 코드는 이 폰의 브라우저 저장소에만 있습니다. 백업 파일에는 들어가지 않고, 복원해도 이 폰의 코드는 그대로 남습니다.

### 새 폰으로 옮기기

1. 새 폰에서 같은 주소를 열고 설정의 "복구 코드로 연결"에 코드를 적습니다(소문자로 적거나 띄어 적어도 됩니다).
2. 클라우드에 있는 백업의 날짜가 나오면 "지우고 복원"을 누릅니다. 새 폰에 있던 기록은 모두 지워지고 백업의 내용으로 바뀝니다.

복원하지 않고 닫으면, 복원할지 새 폰의 기록으로 덮어쓸지 고를 때까지 새 폰은 아무것도 올리지 않습니다. 빈 새 폰이 클라우드의 백업을 덮어 버리지 않게 하기 위해서입니다.

### 알아 둘 점

- **기기 간 동기화가 아니라 백업입니다.** 폰 하나가 기록을 통째로 올리고, 다른 폰은 통째로 받아 옵니다. 두 폰의 기록을 합치지 않습니다. 한 폰에서만 기록하세요.
- 다른 기기가 더 새 백업을 올려 두었으면 올리기를 멈추고 설정 화면에서 고르게 합니다. "클라우드의 백업으로 복원"(이 폰의 기록을 버림)과 "이 폰의 기록으로 덮어쓰기" 중 하나입니다.
- 서버에는 새것부터 10개까지 남습니다. 설정의 "클라우드에서 가져오기"에서 날짜를 골라 예전 것으로 되돌릴 수 있습니다. 하나는 16MB까지입니다.
- "이 폰 연결 끊기"는 이 폰에서 코드만 지웁니다(클라우드의 백업은 남습니다). "클라우드 백업 삭제"는 서버의 백업을 모두 지웁니다.
- 가끔 백업 파일도 받아 두세요. 클라우드 백업은 복구 코드와 Cloudflare 계정이 모두 있어야 되찾을 수 있습니다.

### 저장되는 곳

| 무엇 | 어디에 |
| --- | --- |
| 기록 | 폰의 브라우저(IndexedDB). 클라우드에는 암호문으로 된 사본 |
| 복구 코드, 마지막으로 올린 때와 버전 | 폰의 브라우저에만 (`settings`의 `syncCode`, `syncState`) |
| 암호화된 백업(스냅샷) 10개, 토큰의 SHA-256 | 내 Cloudflare 계정의 Durable Object(`Vault`) 하나 |

서버는 처음 등록한 토큰을 주인으로 삼고, 그 뒤로는 그 토큰이 있는 요청만 받습니다. 그래서 대시보드에 비밀 값을 넣을 필요가 없습니다. 다만 클라우드 백업을 시작하기 전에는 주소를 아는 누구든 먼저 등록할 수 있으니, 쓸 생각이면 배포한 뒤 바로 시작해 두세요.

### 서버

`worker/`에 있고 앱과 같은 Worker로 배포됩니다. `/api/sync/` 로 온 요청만 Worker가 받고, 나머지는 전처럼 정적 파일이 바로 나갑니다. 저장은 SQLite를 쓰는 Durable Object 하나가 맡습니다(무료 요금제에서 쓸 수 있고, KV나 R2, D1은 쓰지 않습니다). `wrangler.jsonc`에 바인딩과 마이그레이션이 적혀 있어서 `npx wrangler deploy`가 알아서 만들고, 대시보드에서 따로 할 일은 없습니다. PR 미리보기는 미리보기마다 빈 보관함을 따로 쓰므로 실제 백업을 건드리지 않습니다.

- `worker/protocol.ts`: 요청을 처리하는 규칙. `worker/sqlStore.ts`: SQLite에 넣고 꺼내기(1MB 조각으로 나눔). `worker/index.ts`: Durable Object와 Worker.
- `src/lib/sync/`: 앱 쪽(복구 코드, 암호화, 서버 호출, 올리기와 가져오기 규칙, 자동 올리기).
- 로컬에서 서버까지 띄워 보려면 `npm run build` 뒤에 `npx wrangler dev`를 씁니다(`npm run dev`와 `npm run preview`에는 서버가 없습니다).

### 복구 코드를 잃어버렸을 때

폰에 기록이 남아 있다면 새로 시작할 수 있습니다. `wrangler.jsonc`의 `vars.VAULT_NAME`(`previews.vars`에도 같은 값이 있습니다)을 `"main"`에서 다른 이름(예: `"main-2"`)으로 바꿔 배포하면 빈 보관함이 됩니다. 그 뒤 앱에서 "이 폰 연결 끊기"를 하고 "클라우드 백업 시작"을 다시 누릅니다. 예전 보관함의 암호문은 이름을 되돌리기 전에는 닿을 수 없는 채로 남습니다.

## 개발

Node.js 22가 필요합니다. 버전은 `.node-version` 파일에 적어 두었고, CI와 배포 빌드도 이 파일을 따릅니다.

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 테스트
npm run lint       # 린트
npm run typecheck  # 타입 검사
npm run build      # dist/ 에 빌드 (타입 검사 포함)
npm run preview    # 빌드 결과를 로컬에서 확인
npm run e2e        # 빌드한 앱을 휴대폰 크기 브라우저로 끝까지 눌러 보는 점검
```

`npm run e2e`는 Playwright로 실제 흐름(운동 기록, 루틴, 통계, 백업, AI 등)을 눌러 봅니다. 처음 한 번 `npx playwright install chromium`으로 브라우저를 받아야 합니다. AI 요청은 흉내 낸 응답으로 대신하므로 실제 API를 부르지 않고 요금도 들지 않습니다. CI에서도 PR마다 돌립니다.

같은 와이파이의 휴대폰에서 개발 서버를 보려면 `npm run dev -- --host`로 띄운 뒤 터미널에 나오는 Network 주소를 엽니다. 오프라인 동작과 홈 화면 설치는 HTTPS로 배포한 주소에서만 확인할 수 있습니다.

### 기술

Vite, React, TypeScript, Tailwind CSS, Dexie(IndexedDB), React Router, vite-plugin-pwa, Vitest, Anthropic TypeScript SDK(AI 추천, 누를 때만 따로 불러옴)

### 구조

```
src/
  db.ts          DB 스키마와 데이터 타입
  seed.ts        기본 종목 목록
  lib/           기록 로직 (운동, 종목, 루틴, 추천, 개인 기록, 통계, 백업, CSV, 설정, 표기, 유산소와 재는 방식, 원판 계산, 웜업, 슈퍼세트, 주간 목표)과 테스트
  lib/ai/        AI 추천 (API 호출과 오류 안내, 보낼 글 만들기, 답 검사와 저장, 모델과 요금, 내 정보, 루틴 만들기)
  lib/sync/      클라우드 백업의 앱 쪽 (복구 코드, 암호화, 서버 호출, 올리기와 가져오기 규칙)
  rest/          휴식 타이머
  stopwatch/     스톱워치 (재는 중인 시간을 폰에 적어 두어 앱을 닫아도 이어진다)
  pages/         화면 (홈, 운동 중, 종목 선택, 운동 완료, 기록, 기록 상세, 루틴, 루틴 편집, 통계, 종목 상세, 체중 기록, 설정)
  components/    여러 화면에서 쓰는 조각 (charts/ 에 직접 그린 SVG 차트)
worker/          클라우드 백업 서버 (Cloudflare Worker와 Durable Object)
e2e/             화면 점검 시나리오와 도우미 (Playwright)
```

데이터는 여덟 개의 테이블로 저장합니다. 통계와 개인 기록은 저장하지 않고 세트에서 그때그때 계산합니다.

| 테이블 | 내용 |
| --- | --- |
| `exercises` | 종목 (이름, 부위, 기구, 목표 횟수, 증량 단위, 휴식 시간, 메모, 재는 방식, 유산소의 거리/층수 선택, 숨김) |
| `workouts` | 운동 한 번 (시작과 끝 시각, 메모, 시작한 루틴) |
| `workoutExercises` | 운동 안에서 한 종목과 순서, 그날의 목표 횟수, 슈퍼세트 묶음 |
| `sets` | 세트 (무게, 횟수 또는 시간, 유산소의 거리와 층수와 강도, 웜업 여부, 완료 여부, RPE) |
| `settings` | 설정 값 |
| `routines` | 루틴 (이름, 종목별 세트 수와 목표 횟수, 슈퍼세트 묶음, 마지막으로 쓴 시각) |
| `aiAdvice` | 받은 AI 답 (운동별 추천과 피드백, 기록 분석과 루틴 제안 한 개씩, 답한 모델, 어림 비용). 백업에는 넣지 않습니다 |
| `bodyWeights` | 체중 기록 (날짜마다 하나) |

모든 id는 UUID 문자열입니다. 나중에 여러 기기의 기록을 합치는 동기화를 붙일 때 그대로 쓸 수 있게 하기 위해서입니다.

테이블 구조를 바꿀 때는 `src/db.ts`에 `this.version(5)`처럼 새 버전을 추가하고(이미 저장된 기록을 옮기는 코드 포함), 백업 파일 형식이 달라지면 `src/lib/backup.ts`의 `BACKUP_VERSION`도 올립니다. 지금은 DB 버전 4, 백업 버전 4이고, 예전에 만든 백업 파일(버전 1~3)도 그대로 복원됩니다. 색인이 없는 필드만 늘릴 때는 DB 버전을 올리지 않아도 됩니다(5단계의 유산소와 슈퍼세트 필드가 그렇습니다).

## 배포

앱은 정적 사이트이고, 클라우드 백업 서버(`worker/`)만 Cloudflare Workers에서 돕니다. 클라우드 백업을 쓰려면 Cloudflare Workers에 올려야 하고, 쓰지 않는다면 `npm run build`로 만든 `dist/` 폴더를 HTTPS를 지원하는 아무 정적 호스팅에 올려도 됩니다.

### Cloudflare

Cloudflare 대시보드에서 이 저장소를 연결하면 `main` 브랜치가 바뀔 때마다 다시 배포됩니다. Workers로 올리는 것을 권합니다(클라우드 백업은 Workers에서만 됩니다).

- **Workers**: 저장소의 `wrangler.jsonc`에 빌드 명령, 정적 파일 위치, 클라우드 백업 서버와 그 저장소(Durable Object)를 적어 두었습니다. 배포 명령은 기본값 `npx wrangler deploy` 그대로 두고(`wrangler versions upload`로는 Durable Object를 만들지 못합니다), 빌드 명령은 비워 두면 됩니다(배포 전에 `npm run build`가 자동으로 실행됩니다). Worker 이름은 `wrangler.jsonc`의 `name`(`health`)과 맞춥니다. 다른 이름을 쓰려면 이 값을 바꿉니다.
  `main`이 아닌 브랜치(PR)의 미리보기 빌드는 설정의 Builds, Previews Base 탭에서 따로 정합니다. Preview command는 기본값 `npx wrangler preview` 그대로 두고 빌드 명령은 비워 둡니다. 이 명령은 `wrangler.jsonc`에 `previews` 항목이 있어야 돌고, 미리보기는 위쪽의 바인딩을 물려받지 않아서 그 안에 클라우드 백업의 바인딩을 다시 적어 두었습니다.
- **Pages**: 프레임워크 프리셋은 없음으로 두고 빌드 명령 `npm run build`, 빌드 출력 디렉터리 `dist`를 입력합니다. 이 경우 `wrangler.jsonc`는 쓰이지 않고 클라우드 백업도 쓸 수 없습니다(설정 화면에 쓸 수 없다고 나옵니다).

휴대폰에서는 배포할 때마다 새로 생기는 미리보기 주소가 아니라 `workers.dev`나 `pages.dev`로 끝나는 고정 주소(또는 연결한 내 도메인)를 열어 주세요.

### 다른 호스팅

Vercel, Netlify 같은 다른 정적 호스팅도 빌드 명령 `npm run build`, 출력 폴더 `dist`로 같은 방식으로 쓸 수 있습니다(클라우드 백업은 빼고).

상대 경로로 빌드하고 `#/history` 같은 해시 주소를 쓰기 때문에, 도메인 루트가 아닌 하위 경로에 올려도 추가 설정 없이 동작합니다.
